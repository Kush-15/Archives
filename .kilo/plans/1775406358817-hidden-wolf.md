# Cart & Navigation UI Diagnosis and Remediation Plan

**Project:** FOEPRO E-Commerce Site  
**Date:** 2026-04-05  
**Priority:** High - Production-blocking issues

---

## Executive Summary

The shopping cart UI displays repetitive "locked/unlocked" console messages, and the cart fails to open consistently on non-Home pages. Additionally, the navigation UI varies between Home and other pages.

### Root Cause Summary

| Issue | Likely Root Cause | Evidence |
|-------|-------------------|----------|
| Rapid locked/unlocked loop | React StrictMode + Loader remounting on non-Home pages | Loader.tsx uses ScrollLockContext which logs on mount/unmount. Home.tsx conditionally renders Loader based on `useLoader` which may not persist across page navigation |
| Cart fails to open on non-Home pages | OverlayContext state not persisting across SPA navigation; potential race between Router re-render and overlay state initialization | SiteNav.tsx correctly calls `overlay.openOverlayByName('cart')` but cart component may not receive updated state |
| Inconsistent navigation UI | Two different SiteNav components with different layouts | `src/components/SiteNav.tsx` (simple, Home only) vs `src/components/ui/SiteNav.tsx` (full-featured with cart/search/icons) |

---

## 1. Concise Summary of Likely Root Causes

### 1.1 Frontend State Logic Issues (React Context/Effects)

- **React StrictMode double-mounting**: `main.tsx` wraps App in `<StrictMode>`, causing useEffect to fire twice in development, leading to rapid lock/unlock cycles
- **Missing dependency arrays**: Loader's first useEffect (lines 46-56) has proper cleanup, but the second useEffect (lines 58-173) may have race conditions with `onDone` callback
- **Context re-rendering on navigation**: OverlayContext resets when navigating between pages due to component tree unmounting/remounting

### 1.2 Concurrency and Race Conditions

- **Overlay state race**: When clicking cart from non-Home page, the `handleCartClick` runs but the OverlayContext may not update before CartSlide renders
- **Loader state not persisted**: `useLoader` in Home.tsx resets on every page navigation, potentially causing Loader to re-mount

### 1.3 Backend Session/Lock Handling

- **No distributed lock in backend**: Backend CartViewSet (`views.py:707`) uses Django ORM only, no Redis or database-level locking
- **Session ID changes**: If session cookies change between requests, cart state may reset

### 1.4 Third-Party Integrations

- **Razorpay keys missing**: `settings.py:416-420` shows RAZORPAY_KEY_ID/SECRET not set - could cause payment-related redirects that interfere with cart

```typescript
// Use sessionStorage to persist overlay state across page navigation
export function OverlayProvider({ children }: { children: ReactNode }) {
  const [openOverlay, setOpenOverlay] = useState<OverlayName>(() => {
    if (typeof window !== 'undefined') {
      const saved = sessionStorage.getItem('overlay-state');
      return (saved as OverlayName) || null;
    }
    return null;
  });

  const openOverlayByName = useCallback((name: Exclude<OverlayName, null>) => {
    setOpenOverlay(name);
    if (typeof window !== 'undefined') {
      sessionStorage.setItem('overlay-state', name);
    }
  }, []);

  const closeOverlay = useCallback(() => {
    setOpenOverlay(null);
    if (typeof window !== 'undefined') {
      sessionStorage.removeItem('overlay-state');
    }
  }, []);
  
  // ... rest of implementation
}
```

### 3.3 Long-Term Improvements (Weeks)

#### Fix 7: Implement Proper Locking with Idempotent API

**Backend:** `Archives/views.py` - Add lock endpoint

```python
from rest_framework.decorators import action
from django.core.cache import cache

class CartViewSet(viewsets.ModelViewSet):
    # ... existing code ...
    
    @action(detail=False, methods=['post'])
    def acquire_lock(self, request):
        cart_id = request.data.get('cart_id')
        owner = request.session.session_key
        lock_key = f'cart_lock_{cart_id}'
        
        # Use SETNX pattern with expiry
        acquired = cache.add(lock_key, owner, 10)  # 10 second TTL
        
        return Response({
            'acquired': acquired,
            'owner': owner if acquired else cache.get(lock_key),
            'ttl': 10
        })
    
    @action(detail=False, methods=['post'])
    def release_lock(self, request):
        cart_id = request.data.get('cart_id')
        owner = request.session.session_key
        lock_key = f'cart_lock_{cart_id}'
        
        if cache.get(lock_key) == owner:
            cache.delete(lock_key)
            return Response({'released': True})
        return Response({'released': False})
```
